1. What the system is

The system is a chat application. Users ask questions. The system answers from the users' own documents. It uses RAG (Retrieval Augmented Generation).

Main ideas:

  • Each user owns separate documents. Users never see other users' data. Retrieval always filters by user_id.
  • The AI (Gemini) only uses retrieved text. If no text fits, it sends a fixed refusal.
  • An agent (Phase 11) can route, retry, and call tools (Phase 12).
  • Auth uses short access tokens and rotating refresh tokens in Redis.

4. Start-up order

The file app/main.py starts in this fixed order:

  1. Read and check JWT settings. Stop fast if they are bad.
  2. Ping Redis. Make session, blacklist, rate-limit, cache services.
  3. Ping MongoDB. Make auth, conversation, document, usage services.
  4. Build Chroma RAG. If the store is empty, load data/*.txt.
  5. Set ready = true only when Chroma holds documents.

/health always sends 200 (liveness). /ready sends 503 until step 5 is done (readiness).

12. How to start the project

12.1 What you need

  • Python 3.13 (repo uses a local .venv). Node 22+. Redis server 7.2+. MongoDB.
  • A .env file with the required keys (see §11).

12.2 Backend (PowerShell)

# 1. Install deps
.venv\Scripts\python.exe -m pip install -r requirements.txt
# 2. Set local env (dev only)
$env:REDIS_URL='redis://localhost:6379/0'; $env:REFRESH_COOKIE_SECURE='false'
# 3. Run the API (reload for dev)
.venv\Scripts\python.exe -m uvicorn app.main:app --reload
# 4. Run backend tests (no live AI needed)
$env:LANGSMITH_TRACING='false'; $env:LANGCHAIN_TRACING_V2='false'
.venv\Scripts\python.exe -m unittest discover -s tests -v

12.3 Frontend (in frontend/)

# Dev server (port 5173, proxies /api to :8000)
npm run dev
# Unit tests / E2E (Edge channel, own dev server)
npm test
npm run test:e2e

12.4 Checks

  • Open http://127.0.0.1:8000/health → {"status":"ok"}.
  • Open http://127.0.0.1:8000/ready → ready only with documents loaded.
  • Full backend suite today: 403 tests (6 known pre-existing SSE/conversation failures, unrelated to agent/tools).

12.5 Docker (Phase 10)

One command starts all services: docker compose up -d --build. Frontend serves on :80. Backend serves on :8000. Full guide: DOCKER_SETUP.html.

14. Design rules

  1. One phase at a time. Finish fully before the next.
  2. Every phase needs tests. No phase ships with red tests.
  3. No breaking changes. Old API shapes stay intact.
  4. All new behavior uses env flags (default off).
  5. Heavy models load on first use, never at start-up.
  6. New services fail gracefully. Old paths still work.
  7. Update docs (AGENTS.md, .env.example) with each phase.
  8. Never trust a refresh JWT without its Redis row. Never store refresh tokens in localStorage.
  9. History resolves references only. History is never a fact source.
