1. What this document is

The system uses external dependencies. The dependencies are Redis, MongoDB, ChromaDB, and the Gemini API. Today you install them on the host machine. This document has two jobs:

  • Job 1: Show how to set up Redis and MongoDB on the host machine. Do this before any container work.
  • Job 2: Show how to put the full system in containers with Docker. This is Phase 10 — Docker Compose.

After Phase 10, one command starts all services: docker compose up -d --build.

2. Words you must know

WordMeaning
ImageA read-only package. It holds the code and the libraries.
ContainerA running copy of an image. It is isolated from the host.
VolumeStorage that lives longer than a container. Data stays after a restart.
ComposeA tool. It starts many containers from one YAML file.
Health checkA small test. Docker repeats it. It shows if a container is ready.
PortA number that identifies a network service. Example: 8000.
Service nameThe name of a container in Compose. Other containers use it as a host name. Example: backend.

4. Set up Redis and MongoDB now

You have two paths. Path A is fast. Path B is a native Windows install.

4.1 Path A — containers for the dependencies (recommended on Windows)

Redis has no official Windows build. Docker is the fastest way on Windows.

# Redis 7.2 with an append-only file in a named volume
docker run -d --name redis-dev -p 6379:6379 -v redis-dev:/data redis:7.2-alpine redis-server --appendonly yes

# MongoDB 7 with a named volume for the data
docker run -d --name mongo-dev -p 27017:27017 -v mongo-dev:/data/db mongo:7

These two containers stay in the background. The backend uses them through localhost.

4.2 Path B — native Windows install

  • MongoDB: Install MongoDB Community Server 7 for Windows. The installer can start MongoDB as a Windows service on port 27017.
  • Redis: Use Memurai (a Redis-compatible Windows server), or install Redis inside WSL2 (sudo apt install redis-server).

4.3 Check the services

# Redis answers PONG
docker exec redis-dev redis-cli ping
# MongoDB answers 1
docker exec mongo-dev mongosh --quiet --eval "db.adminCommand('ping').ok"

For a native install, use mongosh "mongodb://localhost:27017" and a local redis-cli ping.

4.4 The .env file

The backend reads configuration from the environment. Put these keys in the root .env file. Never replace the file. Add the missing keys only.

KeyExampleNotes
JWT_SECRET_KEYa long random stringMust be 32 bytes or more. HS256.
JWT_ISSUERrag-learning-apiDefault value exists.
JWT_AUDIENCErag-learning-api-usersDefault value exists.
REDIS_URLredis://localhost:6379/0Compose overrides this to redis://redis:6379/0.

GEMINI_API_KEY or GOOGLE_API_KEYyour Gemini keyThe google-genai library reads either name. Set exactly one; GOOGLE_API_KEY wins if both exist.
REFRESH_COOKIE_SECUREfalse in devMust be false over HTTP. Keep true in production.
First start needs the Gemini key. If the Chroma collection is empty, the backend reads data/*.txt and makes embeddings. This calls Gemini. Without a Gemini key, the backend stops and restarts in a loop. If data/*.txt is empty, the API still starts, but /ready stays 503 until a user uploads a document. The dev stack bind-mounts app/ and phase1.py, not data/; rebuild the backend image after editing data/*.txt so the new corpus is baked in and ingested on the next start.

5. What Docker is

Docker puts the code, the libraries, and the runtime into one image. The image runs as a container on any machine with Docker. The container uses the same libraries everywhere. This removes the "it works on my machine" problem.

Docker Compose starts five services together. It puts them on one private network. A service finds another service by its name. Example: the frontend finds the backend at http://backend:8000.

6. The backend image

The file Dockerfile (project root) builds the backend image.

FROM python:3.11-slim

# Optional PyPI mirror for slow networks. The default is the official index.
ARG PIP_INDEX_URL=https://pypi.org/simple

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_DISABLE_PIP_VERSION_CHECK=1 \
    PIP_DEFAULT_TIMEOUT=300 \
    PIP_RETRIES=10

WORKDIR /app

COPY requirements.txt .

# Do not upgrade pip: the base image's pip is enough, and this avoids
# one more large download from the package index.
RUN --mount=type=cache,target=/root/.cache/pip \
    pip install torch --index-url https://download.pytorch.org/whl/cpu \
    && attempt=1 \
    && while ! pip install --index-url "$PIP_INDEX_URL" -r requirements.txt; do \
         attempt=$((attempt + 1)); \
         if [ "$attempt" -gt 10 ]; then \
           echo "pip install failed after 10 attempts" >&2; \
           exit 1; \
         fi; \
         echo "pip install failed; retrying ($attempt/10)..." >&2; \
         sleep 5; \
       done

COPY . .

EXPOSE 8000

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
InstructionJob
FROM python:3.11-slimStart from a small Python 3.11 image. All pinned packages support Python 3.11.
ENV ...Unbuffered logs for Docker. No .pyc files.
WORKDIR /appAll later commands run in /app.
COPY requirements.txt .Copy only the requirements first. Docker caches this layer. Code changes do not reinstall packages.
RUN --mount=type=cache ...A BuildKit cache mount holds the pip download cache. The cache is not in the image. A retried build does not download packages again.
pip install torch ... cpuInstall the CPU-only torch first. The reranker is off by default. This saves about 2 GB.
pip install -r requirements.txtInstall the rest of the pinned packages. The bounded retry loop handles a transient truncated download or hash mismatch without failing the whole image build.
COPY . .Copy the application code and data/*.txt. The .dockerignore keeps .env, tests, and caches out of the image.
EXPOSE 8000Documentation only. The port mapping is in the Compose file.
CMD ...Start Uvicorn on all interfaces. No --reload here. The production image is the default.

7. The frontend image

The file frontend/Dockerfile uses two stages. Stage 1 builds the React files with Node. Stage 2 serves the files with nginx. The build tools do not go into the final image.

FROM node:22-alpine AS build

WORKDIR /app

COPY package.json package-lock.json ./
RUN npm ci

COPY . .
RUN npm run build

FROM nginx:1.27-alpine

COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html

EXPOSE 80
StageJob
node:22-alpine AS buildBuild stage. npm ci installs exact locked packages. npm run build makes frontend/dist.
nginx:1.27-alpineRun stage. Copy only dist and the nginx configuration. The image stays small.

The file frontend/nginx.conf serves the site and proxies the API. It keeps the same-origin rule. The browser talks only to nginx.

server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    client_max_body_size 10m;

    location /api/ {
        proxy_pass http://backend:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }

    location = /health {
        proxy_pass http://backend:8000/health;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location = /ready {
        proxy_pass http://backend:8000/ready;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
RuleWhy
proxy_pass http://backend:8000backend is the Compose service name. Docker DNS finds it.
proxy_buffering offThe chat answer is an SSE stream. Buffering would delay the tokens.
proxy_read_timeout 300sAgent loops and long answers need more than 60 seconds.
client_max_body_size 10mDocument uploads. The app limit is 5 MB by default.
try_files ... /index.htmlReact single-page app. Unknown paths return index.html.

8. ChromaDB: two modes

The backend supports two Chroma modes. The environment variable CHROMA_URL selects the mode.

ModeCHROMA_URLClientData lives in
Embedded (default)not setchromadb.PersistentClientchroma_data/ on the local disk.
Server (containers)http://chroma:8000chromadb.HttpClientThe chroma-data named volume.

The function phase1.build_chroma_client makes the client. An empty or absent URL keeps the old embedded behavior. Nothing breaks for local development.

The two modes use different clients. Do not point them at the same data directory at the same time.

9.5 The production override

The file docker-compose.prod.yml changes three things: no reload, secure cookies, and nginx with TLS on port 443.

services:
  backend:
    command: ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
    environment:
      REFRESH_COOKIE_SECURE: "true"
    volumes:
      - uploads-data:/app/uploads

  frontend:
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./certs:/etc/nginx/certs:ro
      - ./frontend/nginx.prod.conf:/etc/nginx/conf.d/default.conf:ro

Put the TLS files in the certs/ folder:

  • certs/server.crt — the certificate.
  • certs/server.key — the private key.

For a local test, make a self-signed certificate with OpenSSL:

openssl req -x509 -newkey rsa:2048 -nodes -keyout certs/server.key -out certs/server.crt -days 365 -subj "/CN=localhost" -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"

The file frontend/nginx.prod.conf listens on 443 with TLS. Port 80 answers with a redirect to HTTPS. The proxy rules are the same as in the development file.

10. Run and check

10.1 Development stack

# 1. Start Docker Desktop first. Check the engine:
docker info

# 2. Validate the files without starting anything:
docker compose config -q

# 3. Build the images and start all services:
docker compose up -d --build

# 4. Wait, then read the status. All services must be healthy:
docker compose ps

# 5. Check the endpoints:
Invoke-WebRequest http://localhost:8000/health
Invoke-WebRequest http://localhost/health
Invoke-WebRequest http://localhost/

Open http://localhost in the browser. Register a user. Upload a non-empty .txt file, then ask a question. The first start also ingests data/*.txt into Chroma for the eval_user tenant. This takes a moment and needs the Gemini key. If data/*.txt is empty, the backend is still live on /health but /ready returns 503 until a document is uploaded.

10.2 Production stack (local test)

# 1. Make the TLS files (see section 9.5)
mkdir certs
openssl req -x509 -newkey rsa:2048 -nodes -keyout certs/server.key -out certs/server.crt -days 365 -subj "/CN=localhost" -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"

# 2. Start with both compose files. The second overrides the first:
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build

# 3. Check 443
Invoke-WebRequest https://localhost/health -SkipCertificateCheck

10.3 Stop the stack

docker compose down
Data loss warning. docker compose down -v also deletes the named volumes. All users, chats, uploads, and vectors are lost.

11. Problems and fixes

SymptomCauseFix
Port 80 is already in useIIS or another web server holds port 80.Change the frontend mapping to "8080:80". Open http://localhost:8080.
The backend container restarts in a loopGEMINI_API_KEY (or GOOGLE_API_KEY) or JWT_SECRET_KEY is missing in .env.Add the key. Run docker compose up -d again. Read the log with docker compose logs backend.
Login works, but refresh fails over HTTPREFRESH_COOKIE_SECURE=true on an HTTP page.Use the base compose file. It sets the value to false. Use true only with TLS.
The image is very largetorch with CUDA libraries.Keep the CPU-only torch step in the Dockerfile. The reranker stays off by default.
The pip download is very slow or times outfiles.pythonhosted.org is slow on your network.Build with a mirror, for example docker compose build --build-arg PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ backend. The default remains the official index.
The frontend build stops on Nodefrontend/package.json requires Node 22.12 or later.Keep the Dockerfile on node:22-alpine (or newer).
Chroma health check failsThe upstream image has no Python or curl; the thin chroma/Dockerfile adds curl.Rebuild with docker compose build --no-cache chroma. Keep the pinned base chromadb/chroma:1.5.9.
Streaming looks slow or blockedA proxy buffers the SSE stream.Keep proxy_buffering off in the /api/ location.
Uploads return 413The nginx body limit is too low.Keep client_max_body_size 10m. It is higher than MAX_UPLOAD_BYTES.
Data disappears after a restartVolumes were removed with down -v.Do not use -v in normal operation. Check volumes with docker volume ls.

12. Safety rules

  1. Never put secrets in an image. Keep .env in .dockerignore.
  2. Never commit .env, TLS files, or volumes. certs/, chroma_data/, and uploads/ are ignored by Git.
  3. Keep the access rules. The browser talks only to nginx. The Gemini key stays on the server.
  4. Keep REFRESH_COOKIE_SECURE=true in production. Use false only for local HTTP development.
  5. Pin image versions. Unpinned tags change without warning.
  6. Do not use docker compose down -v on a system with real data.
  7. One phase at a time. Phase 9 (pytest migration) is still open. Phase 10 does not block it.
